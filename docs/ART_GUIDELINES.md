# oddex 角色美術準則（GBA 第三世代風格）

> **2026-11-20 更新（使用者決定）**：手工像素的 Kamorai 試點（`tools/oddex/pixelkit.py`）看過之後，使用者認為**最初的 Blender 立體版本最好看、最帥**。所以既有角色維持 Blender 版，手工像素不推廣。下面的原則仍適用於之後新做的角色和對 Blender 版的修整（Brief、輪廓、表情、清雜點、在遊戲裡看），但「不要渲染後縮小」這條不再是硬性規定。

使用者 2026-11-20 的評語：「大多角色都很醜」。原因是我們把**角色設計**當成**圖片處理**在做：Blender 渲染後縮小、自動量化，得到的是雜點和破碎色塊，不是像素構圖。這份準則取代「渲染再縮小」的做法。

## 原則

1. **先設計角色，再畫像素。** 每隻角色先寫一份 Character Design Brief（見下方），定案後才產生 sprite。
2. **輪廓比細節重要。** 整隻塗黑也要認得出來：大頭、多手、長舌、怪頭型、誇張姿勢。
3. **畫布 64×64 不必塞滿。** 留白讓輪廓清楚；角色主體通常佔 40–56 px。
4. **顏色越少越好。** 目標 8–12 色（上限 15 色加透明）：1–2 個主色、1 個輔助色，每個區域 2–3 階明暗。不用漸層、不用照片紋理。
5. **表情要極端，但不要笑臉。** 嘴太大、眼神呆滯、瞪大的眼、空洞的眼窩；面具系列維持「傳統日式恐怖」（`docs/DECISIONS.md`）。**不畫笑臉**（使用者 2026-11-22）：不要笑到瞇起來的弧形眼、不要上揚的嘴角、不要露齒的笑。嘴可以張開（嘶吼、呆滯、垂下來），但不能是在笑。原型本身在笑的（猩々、嘯、翁這類面具），改成瞪眼、呆滯或嚴肅的版本。
6. **真正的像素圖。** 像素網格一致、沒有半透明、沒有孤立的雜點、色塊連續、1 px 輪廓粗細一致。不是「高解析圖加馬賽克」。
7. **同一隻角色。** 正面、背面、icon、overworld 都從同一份 Brief 和同一組調色盤做出來，不是各自重新生成。
8. **一定要放進遊戲看。** 兩個檢查都要過：放大視圖看輪廓和色塊；1× 遊戲畫面（戰鬥、能力畫面、畫廊）看辨識度。程式驗證通過不等於美術完成。

例外（使用者決定）：三人組御三家維持照片合成的寫實臉。

## Character Design Brief（每隻一份，寫進 `docs/research/mask-designs.md` 或 `friends-designs.md`）

- 一句話概念：這是什麼、為什麼好笑或可怕。
- 輪廓特徵：塗黑後靠哪 1–2 個形狀辨認。
- 表情：要讓人記住的那一個表情（不能是笑臉，見原則 5）。
- 調色盤：主色、輔助色、明暗階數，總色數。
- 正面和背面各要看得到什麼。
- 至少 2 個設計方案，選一個並寫理由。

## 製作流程

1. Brief 定案。
2. 用 SpriteCook 產生概念或 sprite 初稿（見下方的費用規則），或其他來源。
3. 像素層級修整：統一輪廓、清掉雜點、合併相近色、套到 15 色以內的調色盤（`tools/oddex/import_art.py` 只處理格式，不負責美感）。
   - Blender 模型的角色：渲染縮到 64 px 之後，眼睛這類小特徵會變成雜點。在模型檔裡寫一個 `PIXELS` 表（手擺的像素，見 `tools/oddex/blender/make_art.py` 的 `apply_pixels`），`make_art` 每次重新產生都會把它蓋回正面兩幀和 icon。顏色用調色盤裡已有的顏色，而且要選異色調色盤裡不會變掉的（例如輪廓色）；模型改到 sprite 位置變了，`make_art` 會報錯要求重畫，不會把眼睛畫錯位置。
4. 產生正面、第二幀、背面、icon、overworld、異色（同一組索引換色）。
5. `make check-oddex` 加上逐張看畫廊、能力畫面、戰鬥截圖。
6. **先把一隻做到真正好看**，給使用者看過，再推廣到其他角色。試點：一隻面具角色。
